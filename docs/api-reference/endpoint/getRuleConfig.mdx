# Get Rule Config

## Use case

Fetches a service-level success-rate or elimination configuration for a merchant.

## Authentication

Protected. Send either `Authorization: Bearer <jwt_token>` or `x-api-key: <api_key>`. In sandbox, also send `x-feature: decision-engine`.

For local development, start with:

```bash
export BASE_URL=http://localhost:8080
export AUTH_HEADER="Authorization: Bearer <jwt_token>"
# Sandbox only:
# export BASE_URL=https://sandbox.hyperswitch.io
# export FEATURE_HEADER="x-feature: decision-engine"
```

## Request

- Method and path: `POST /rule/get`
- Parameters: none.
- Body: JSON body with `merchant_id` and `algorithm` (`"successRate"` or `"elimination"`).

## Example

### Get success-rate config

```bash
curl --location "$BASE_URL/rule/get" \
  --header "$AUTH_HEADER" \
  --header "Content-Type: application/json" \
  --data '{
  "merchant_id": "merchant_demo",
  "algorithm": "successRate"
}'
```

### Get elimination config

```bash
curl --location "$BASE_URL/rule/get" \
  --header "$AUTH_HEADER" \
  --header "Content-Type: application/json" \
  --data '{
  "merchant_id": "merchant_demo",
  "algorithm": "elimination"
}'
```

## Response

```json
{
  "merchant_id": "merchant_demo",
  "config": {
    "type": "successRate",
    "data": {
      "defaultLatencyThreshold": null,
      "defaultBucketSize": 20,
      "defaultHedgingPercent": null,
      "margin": 0.2,
      "subLevelInputConfig": [
        { "paymentMethod": "CARD", "paymentMethodType": null, "bucketSize": 30, "hedgingPercent": 0.05 }
      ]
    }
  }
}
```

## Notes

- An existing merchant with no saved configuration returns HTTP 200 with `{"merchant_id":"merchant_demo","config":null}`. The dashboard treats this as not configured and uses its default-settings state. This also applies immediately after deleting a configuration.
- An unknown merchant returns HTTP 404. Configuration storage read failures and malformed stored configurations also return HTTP 404, with the underlying error retained in server logs.
- Create and update requests still require a concrete `config`; only the fetch response permits `null`.
- Use this to determine overview setup readiness.
