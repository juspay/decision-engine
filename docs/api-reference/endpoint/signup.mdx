# Signup

## Use case

Creates a dashboard operator account and associates it with the initial merchant workspace.

## Authentication

Requires the deployment's admin secret in the `x-admin-secret` header — signup is not a public endpoint. No JWT or API key is required. Sandbox traffic may still include `x-feature: decision-engine` when routed through Hyperswitch.

For local development, start with:

```bash
export BASE_URL=http://localhost:8080
export ADMIN_SECRET="<deployment_admin_secret>"
# Sandbox only:
# export BASE_URL=https://sandbox.hyperswitch.io
# export FEATURE_HEADER="x-feature: decision-engine"
```

## Request

- Method and path: `POST /auth/signup`
- Headers: `x-admin-secret: <deployment_admin_secret>` (required).
- Parameters: none.
- Body: JSON body with `email`, `password`, and merchant identifier/name depending on the dashboard onboarding flow. Passwords must satisfy the dashboard policy.

## Example

### Create account

```bash
curl --location "$BASE_URL/auth/signup" \
  --header "Content-Type: application/json" \
  --header "x-admin-secret: $ADMIN_SECRET" \
  --data '{
  "email": "operator@example.com",
  "password": "StrongPass#123",
  "merchant_id": "merchant_demo"
}'
```

## Response

```json
{
  "token": "eyJ...",
  "user_id": "user_123",
  "email": "operator@example.com",
  "merchant_id": "merchant_demo",
  "role": "admin",
  "merchants": [
    {
      "merchant_id": "merchant_demo",
      "merchant_name": "Demo Merchant"
    }
  ]
}
```

## Notes

- If the email already exists, redirect the user to login rather than creating a duplicate account.
- Use at least 10 characters with uppercase, lowercase, number, and special character.
