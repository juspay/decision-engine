# Create Success Rate Config

```bash
curl --location "$BASE_URL/rule/create" \
  --header "$AUTH_HEADER" \
  --header "Content-Type: application/json" \
  --data '{
    "merchant_id": "merchant_demo",
    "config": {
      "type": "successRate",
      "data": {
        "defaultBucketSize": 20,
        "defaultLatencyThreshold": null,
        "defaultHedgingPercent": null,
        "margin": 0.20,
        "subLevelInputConfig": [
          {
            "paymentMethod": "card",
            "bucketSize": 30,
            "hedgingPercent": 0.05
          }
        ]
      }
    }
  }'
```

`subLevelInputConfig` is an **array** of per-dimension overrides. Each entry carries the dimension keys it applies to alongside the override values (`bucketSize`, `hedgingPercent`, `latencyThreshold`, …):

- `paymentMethod` (required) is the payment method category, in Hyperswitch's meaning: `card`, `wallet`, `upi`.
- `paymentMethodType` (optional) is the specific method within it: `credit`, `google_pay`. Leave it out to cover the whole method.
- `cardNetwork`, `cardIsIn`, `currency`, `country`, `authType` narrow the row further.

Rows are checked when saved: an unknown method, a type that does not belong to its method, or a row with the two the legacy way round (`"paymentMethodType": "CARD"`) is rejected with a 400. Saved rows store the method and type as upper-case codes (`CARD`, `CREDIT`), which is how `/rule/get` returns them.

```json
{
  "message": "Success Rate Configuration created successfully",
  "merchant_id": "merchant_demo",
  "config": {
    "type": "successRate",
    "data": {
      "defaultBucketSize": 20,
      "defaultLatencyThreshold": null,
      "defaultHedgingPercent": null,
      "margin": 0.20,
      "subLevelInputConfig": [
        { "paymentMethod": "CARD", "paymentMethodType": null, "bucketSize": 30, "hedgingPercent": 0.05 }
      ]
    }
  }
}
```

`margin` is the merchant margin as a fraction of ticket (e.g. `0.20` for 20%). It feeds the [multi-objective routing](https://github.com/juspay/decision-engine/blob/main/docs/api-refs/decide-gateway-multi-objective.mdx) economic-value ranking `EV = auth rate × settlement value` (settlement value = txn amount − cost of payment processing) by setting the merchant's share of the ticket, and defaults to `1.0` when unset.
